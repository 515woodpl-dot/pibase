# M1 gate report

Date: 2026-09-30

## Result

M1 implements the planned data API and SQL milestone on the Raspberry Pi 4.
The API was exercised through both direct real-PostgreSQL integration tests and
the real `@supabase/supabase-js` client. PostgreSQL, not application-side row
filtering, enforces role grants and RLS.

## Built

### Request security boundary

- API keys are resolved by constant-time comparison of SHA-256 hashes stored in
  the control database.
- Per-project AES-GCM-encrypted JWT secrets are decrypted only inside the
  gateway. HS256 signatures, issuer, issue time, expiry, and allowed roles are
  verified.
- Anon, authenticated, and service JWTs map only to that project's roles.
  Service JWT use additionally requires the matching service API key.
- Each request uses a transaction with `SET LOCAL ROLE`,
  `request.jwt.claims`, and a five-second statement timeout.
- Project pools keep zero idle connections and a global 32-slot database
  semaphore stays below PostgreSQL's 40-connection budget.
- Responses are buffered until the transaction commits, so a failed commit or
  post-write quota check cannot return a false success.

### REST subset

- `GET`/`HEAD`: projection, typed filters (`eq`, `neq`, `gt`, `gte`, `lt`,
  `lte`, `like`, `ilike`, `in`, `is`), order, limit/offset, exact counts,
  singular responses, and a 1,000-row cap.
- `POST`, `PATCH`, and `DELETE`: JSON writes, minimal or representation
  responses, and conflict-target merge upsert.
- Named-argument RPC for accessible functions.
- One-level embedding in both foreign-key directions for single-column foreign
  keys.
- Catalog validation for every table, column, relationship, function, and type
  name. Dynamic identifiers use PostgreSQL identifier quoting; values remain
  parameters.
- PostgREST-shaped JSON errors, useful HTTP status mapping, and browser CORS
  headers.

### SQL, migrations, and limits

- Operator-only `migration-apply` and `sql` commands select the project by ID,
  connect only to its database, and `SET LOCAL ROLE` to its admin role.
- Migrations are transactional, advisory-lock serialized, idempotent, and
  checksum protected. Owner SQL has a 30-second timeout and is never exposed on
  the public HTTP API.
- One MiB request-body cap, 100 requests/second per-project window, daily
  request counters, and a default 1 GiB database-size quota checked before and
  after write-capable transactions.
- A `project-delete` operator command supports deterministic cleanup of
  temporary acceptance projects.

## Verification

`./scripts/test.sh` passed on 2026-09-30:

- `gofmt`, `go vet ./...`, and all unit tests passed.
- Real-PostgreSQL tests passed serially. They cover database/role isolation,
  encrypted secrets, anon/authenticated/service RLS, JWT claim propagation,
  CRUD, typed filtering, ordering, upsert, exact-count behavior, RPC,
  forward/reverse embedding, migration idempotency, owner SQL role isolation,
  usage counting, size-quota rejection, invalid keys, and unsupported syntax.
- The distroless production image built as `pibase:m1`.
- The stripped static Linux ARM64 build passed.

`./scripts/test-supabase-js.sh` also passed. It created an isolated temporary
project, applied a real migration, and used `@supabase/supabase-js` 2.117.2 for
insert, select, RLS filtering, exact count, ordering/range, embedding, update,
upsert, RPC, and delete. Its cleanup removed the temporary project.

The ignored standalone artifact is `bin/pibase-linux-arm64`. It is a stripped,
statically linked ARM aarch64 ELF, 9,568,408 bytes, with SHA-256
`65e8f857504ccf4ccd3cc44ff4e6e03e35e6f968161b12addb4f243e35e9e021`.

## Explicit subset boundaries

These inputs return clear errors instead of being silently approximated:

- logical `or`/`not`, full-text search, JSON-path operators, computed columns,
  aliases, and nested embedding;
- multi-column foreign-key embedding;
- overloaded functions and functions with unnamed input arguments;
- schemas other than `public` through the REST endpoint.

Auth user-management endpoints are M2, storage is M3, operations/dashboard and
browser owner SQL UI are M4, and realtime is M5. M1 accepts already-issued
authenticated JWTs so its RLS context can be tested before M2 creates them.

## Not tested

- Sustained or adversarial load, latency/throughput targets, failover,
  power-loss recovery, and storage endurance.
- PostgreSQL data types beyond those covered by the integration fixture.
- Cross-origin behavior in a browser engine; headers are checked by code and
  the JavaScript acceptance runs under Node 22.
- More than 100 requests/second behavior through a distributed multi-gateway
  deployment. The M1 limiter is intentionally per process.

## Known operational notes

- The Compose project retains its historical `pibase-m0` name so the measured
  M0 volume remains reproducible; production image tagging and this report use
  M1.
- The integration test temporarily assigns a known authenticator password.
  `scripts/test.sh` now uses a trap to restore the configured password on both
  success and failure.
- Database-size checks use `pg_database_size`; a transaction that crosses the
  quota is rolled back before its buffered response is released.
