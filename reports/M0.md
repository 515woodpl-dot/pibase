# M0 gate report

Date: 2026-09-30

## Result

M0 passes its foundation and measurement gate on the Raspberry Pi 4 used for
this run. Twenty active projects fit comfortably inside the 4 GB target. The
100-project light-load scenario also completed within the configured
PostgreSQL `max_connections=40` limit.

## Built

- One Go gateway binary with `GET /healthz` and project-creation commands.
- One PostgreSQL 16 cluster with a `_control` database and one database per
  project.
- Per-project anon, authenticated, service, and admin roles and signed anon and
  service keys.
- AES-GCM encryption at rest for project JWT secrets.
- Compose bootstrap and production distroless image.
- An M0 measurement harness for 1, 20, and 100 projects in idle and light-load
  modes. Light load runs at most 20 project queries concurrently.

## Verification

`./scripts/test.sh` passed on 2026-09-30:

- `gofmt`, `go vet ./...`, and `go test ./...` passed.
- The real-PostgreSQL integration test passed. It verifies cross-project
  database isolation, the authenticator's `NOSUPERUSER NOINHERIT` attributes,
  denial of anon access to the `auth` schema, distinct anon/service keys, and

## Measured memory

Host: Raspberry Pi 4, aarch64 Linux, 3,794 MiB RAM. PostgreSQL was configured
with 128 MiB shared buffers, 40 maximum connections, and 4 MiB work memory.
Each value below is the mean of three samples; the parenthesized value is the
largest sample. Values are process RSS reported by `docker top`.

| Projects | Mode | Gateway MiB | PostgreSQL summed MiB | Combined MiB |
|---:|---|---:|---:|---:|
| 1 | idle | 9.5 (9.5) | 98.8 (98.8) | 108.3 |
| 1 | light | 11.3 (11.6) | 98.9 (98.9) | 110.2 |
| 20 | idle | 9.8 (9.8) | 161.5 (163.1) | 171.4 |
| 20 | light | 15.5 (15.7) | 316.9 (406.6) | 332.4 |
| 100 | idle | 10.8 (10.8) | 326.5 (326.5) | 337.3 |
| 100 | light | 15.5 (15.6) | 419.4 (500.8) | 434.9 |

The largest independently sampled gateway-plus-PostgreSQL value was about
516.4 MiB (15.6 + 500.8 MiB) in the 100-project light-load scenario. At 20
projects it was about 422.4 MiB. Summing PostgreSQL process RSS can count shared
pages more than once, so these figures are conservative and must not be added
to host-wide `used` memory as if they were unique resident pages.

The raw samples and environment capture are in `reports/raw/m0-memory.csv` and
`reports/raw/m0-environment.txt`. The harness-captured gateway log contains no
failed measurement queries during its sampling windows. The 100-project light
loop remained running after the harness completed and later logged two
2-second query timeouts before the verification suite changed the test role's
password. This does not affect the recorded RSS samples or the 20-project gate,
but it is evidence that the 100-project case needs a longer-duration load test
before making a sustained-capacity claim.

The measurement harness now records PSS from `/proc/*/smaps_rollup` alongside
the legacy summed-RSS columns; the committed capture above predates that column
addition and is retained as the original raw run.

## Not tested in M0

- REST, auth, storage, realtime, dashboard, backup, and migration features
  assigned to later milestones.
- Sustained load, request latency/throughput, failover, power-loss recovery,
  and storage endurance.
- A clean dedicated host baseline. Other services were running on this Pi and
  swap was already full, so only the isolated container process RSS is used for
  the gate decision.
- Real customer workloads or more than 100 provisioned projects.

## Known gaps

- M0 light load is synthetic (`SELECT 1`) and measures connection/process
  overhead, not application-query cost.
- The three five-second sampling windows are sufficient for the M0 memory
  snapshot, not for a sustained-load reliability claim.
- PostgreSQL summed RSS is intentionally retained as the reproducible harness
  metric, despite its shared-page double-counting limitation.
- Measurement containers and their dedicated volume remain available for
  audit; they can be removed with `docker compose down --volumes` from this
  repository.
