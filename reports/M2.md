# M2 gate report

Date: 2026-09-30

## Result

M2 adds per-project password authentication and authenticated JWT/RLS context.
Each project now owns its auth tables and `auth.uid()` function; auth data is
not exposed through the public REST surface.

## Implemented

- Argon2id password hashing with password-strength bounds.
- Signup, email confirmation, password login, refresh-token rotation,
  recovery-token issuance/verification, and authenticated `/auth/v1/user`.
- Access JWT claims include `sub`, `email`, `role=authenticated`, `aud`, and
  session identifiers. Opaque action/refresh tokens are stored as SHA-256
  hashes and expire server-side.
- Service-key-only admin list/create/update/delete endpoints.
- Locked-down `auth.uid()` SECURITY DEFINER function reading request claims;
  anon/authenticated/service roles have no auth-table privileges.

## Verification

- Containerized `gofmt`, `go vet ./...`, and `go test ./...` passed.
- Real PostgreSQL control/gateway integration passed, including role/database
- isolation after adding the auth schema. The M2 integration test covers
  `auth.uid()` RLS, reset-password replacement, refresh rotation/replay
  rejection, and service-admin boundaries.
- The real `@supabase/supabase-js` acceptance passed signup, confirmation,
  password login, refresh, recovery/reset, data API operations, and admin
  create/delete.
- The production distroless image built successfully as `pibase:m2` and the
  consolidated `scripts/test.sh` gate passed.
- The standalone static ARM64 artifact is `bin/pibase-linux-arm64`, SHA-256
  `b9b8359f91e9f53d3f97facc7dd66384f11ca4a9878147a94bce2eb9c5b41974`.

## Not tested / explicit boundaries

- No outbound mail provider is bundled in M2. Confirmation and recovery
  tokens are delivered only when `PIBASE_AUTH_EXPOSE_TOKENS=true` for the
  acceptance harness; production integration must provide a mail delivery
  adapter before exposing those flows to end users.
- OAuth, MFA, phone/SMS, SAML, and sustained adversarial load remain outside
  the M2 contract.
