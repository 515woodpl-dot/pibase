# M2 gate report

Date: 2026-09-30

## Result

M2 adds per-project password authentication and authenticated JWT/RLS context.
Each project now owns its auth tables and `auth.uid()` function; auth data is
not exposed through the public REST surface.

## Implemented

- Argon2id password hashing with password-strength bounds.
- Signup, email confirmation, password login, refresh-token rotation,
  recovery-token issuance/verification, and authenticated `/auth/v1/user`.
- Access JWT claims include `sub`, `email`, `role=authenticated`, `aud`, and
  session identifiers. Opaque action/refresh tokens are stored as SHA-256
  hashes and expire server-side.
- Service-key-only admin list/create/update/delete endpoints.
- Locked-down `auth.uid()` SECURITY DEFINER function reading request claims;
  anon/authenticated/service roles have no auth-table privileges.

## Verification

- Containerized `gofmt`, `go vet ./...`, and `go test ./...` passed.
- Real PostgreSQL control/gateway integration passed, including role/database
  isolation after adding the auth schema.
- Manual real-gateway flow passed: signup, confirmation, password login, and
  bearer `/auth/v1/user` retrieval.
- Supabase JS acceptance now covers signup, confirmation, password login, and
  refresh in addition to the M1 data API checks.
