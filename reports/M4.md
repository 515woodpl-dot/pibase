# M4 operations — implementation complete, audit pending

## Status

M4 is implemented on branch `pibase/m4`. The implementation and regression
gates pass; this report is ready for the independent M4 audit. No release or
merge is claimed by this report.

## Built

- Operator inventory and 30-day request usage commands without secret fields.
- Prometheus text metrics for health, uptime, Go heap, request count, open
  pools, and per-project request/database/file-storage usage.
- Static `/dashboard` with no Node runtime. Its API requires an exact bearer
  `PIBASE_OPERATOR_TOKEN`, uses no browser persistence, and serves no keys.
- Owner SQL UI using the existing project-admin execution path, 30-second
  timeout, 1,000-row cap, and authenticator connection boundary.
- Authenticated streaming backup format using independent `PIBASE_BACKUP_KEY`,
  64 KiB secretbox frames, atomic finalization, project manifest, PostgreSQL
  custom dump, and object files.
- Guarded restore requiring `PIBASE_RESTORE_CONFIRM`, authenticated archive
  validation, project-id/database matching, preserved database ownership/ACLs,
  and retained pre-restore file tree.
- `project-branch`: fresh roles/JWT/API keys and a clone of only `public`
  schema/data. Auth identities, sessions, storage metadata, and object files
  are intentionally excluded. Public grants and role-specific RLS policies are
  remapped without rewriting ordinary row data.
- Idempotent Pi host setup plus SSD, deployment, monitoring, backup, restore,
  and quarterly-drill runbook.
- A small distroless gateway target and separate ephemeral `ops` image target
  containing PostgreSQL 16 client tools; no additional production service.

## Audit notes and known scaling limits

- **Fixed during M4 debug:** raw owner-SQL and migration commands formerly
  accepted a superuser URL. PostgreSQL accepts comments between `RESET SESSION
  AUTHORIZATION` tokens, so a submitted statement could recover that superuser
  session. These paths now require an `authenticator` connection and use only
  `SET LOCAL ROLE`; regression coverage rejects privileged URLs before any
  connection is opened.
- **Fixed during M4 debug:** the encrypted backup reader authenticated frames
  but accepted bytes appended after its authenticated terminator. It now rejects
  all trailing data, with a regression test for append tampering.

- `findPublicObject` still scans the project catalog for a no-key public object.
  This is O(projects) cross-project work. It is acceptable at the measured
  roughly-20-project Pi target, but project-id routing (path or subdomain) should
  precede materially larger catalogs.
- `validateOwnerSQL` remains a keyword blocklist, not a SQL parse tree. It is
  defense-in-depth only. The effective privilege boundary is a connection as
  `authenticator`, followed by the selected project admin role; superuser URLs
  are rejected for raw SQL so comment-obfuscated session resets cannot
  re-escalate privileges.
- Metrics/dashboard project aggregation is also O(projects) and walks each
  project file directory. Scrape/refresh intervals should remain low-frequency
  on the Pi.
- Backup files protect confidentiality and integrity, but availability still
  requires copying them off the Pi and retaining the backup key separately.
