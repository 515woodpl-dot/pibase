# M4-01 Gate Report — structural branch role remapping

**Branch:** `pibase/m4-01`
**Status:** APPROVED WITH NO BLOCKING FINDINGS

## Acceptance items

- [x] Branch creation clones only the source `public` schema and data.
- [x] No source role name is rewritten in dump text; grants, default
  privileges, table/sequence/schema ACLs, and RLS policy role lists are read
  from PostgreSQL catalogs and recreated against fresh branch roles.
- [x] Policy expressions and ordinary row data remain byte-for-byte equivalent
  apart from PostgreSQL's normal dump/restore representation.
- [x] Auth/storage schemas, users, sessions, storage metadata, and object files
  remain excluded.
- [x] A live branch attack proves source and branch roles cannot cross-connect
  or read each other's data, while branch anon/authenticated/service/admin
  behavior remains correct.
- [x] Formatting, vet, full tests, live PostgreSQL integration, and arm64 build
  pass.

## Pre-build decision

The branch path will use catalog-driven SQL emitted by the source database and
executed on the target database. `pg_dump` remains useful for ordinary public
schema/data objects, but its ACL and policy statements are not trusted as a
text-rewrite interface. Customer SQL is never parsed or executed on the
operator connection; only catalog rows are converted into identifier-safe
statements.

## Adversarial audit

- No dump-text role substitution remains, so role-like strings in policy
  expressions or data are not rewritten accidentally.
- The target is deleted on any dump, restore, catalog-read, mapping, or SQL
  error. Remapping runs in one target transaction after restore, and schema
  ACLs are reset for the fresh roles and `PUBLIC` before source ACLs apply.
- Default-privilege rows are restricted to the public schema; auth/storage
  defaults cannot be copied. ACL privilege and relation-kind values are
  allow-listed before SQL generation.
- The live test did not exercise every PostgreSQL object kind (functions,
  sequences, column ACLs, or multiple-role policies); those paths are READ
  from catalog queries and remain lower-confidence than the exercised table
  and policy path.
